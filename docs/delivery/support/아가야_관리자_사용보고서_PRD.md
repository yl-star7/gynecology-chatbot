# 아가야 관리자 사용 보고서 PRD

**문서 목적**: 앱 화면에서 보이는 문구와 정보가 관리자 화면의 어느 메뉴에서 수정되는지 매칭해, 완료보고서와 별개로 운영자가 확인할 수 있는 사용 보고서로 제공한다.  
**문서 성격**: 완료보고서가 아니라 `관리자 사용 보고서`다. 개발 완료 여부 증빙보다, 앱 화면과 관리자 수정 위치를 연결하는 운영 안내가 목적이다.  
**작성일**: 2026년 5월 11일

---

## 1. 배경

전달받은 앱 화면은 사용자 앱 기준으로는 익숙하지만, 관리자 화면은 동일해 보이는 편집 화면이 많고 어떤 항목이 실제 앱의 어느 영역에 반영되는지 구분하기 어렵다.

특히 `15주 2일`처럼 앱에 직접 크게 보이지 않거나 일부 화면에서만 표시되는 정보가 관리자 화면에는 보이는 경우가 있다. 이 값은 콘텐츠 문구가 아니라 사용자 임신 주차/일차 상태값이므로, 콘텐츠 편집 영역과 분리해서 설명해야 한다.

따라서 완료보고서에 단순히 기능 목록을 넣기보다, 별도 `사용 보고서`로 아래 질문에 답하는 문서를 만든다.

- 이 앱 화면 문구는 관리자 어디에서 바꾸나요?
- 이 값은 콘텐츠인가요, 사용자 상태값인가요?
- 관리자에서 직접 수정 가능한가요, 조회만 가능한가요?
- 수정 후 앱에서 어디에 반영되나요?

---

## 2. 대상 사용자

### 2.1 교수님/운영 담당자

앱 화면을 보면서 콘텐츠를 검수하고, 문구 수정 요청을 관리자 메뉴 기준으로 전달해야 한다.

필요한 정보:
- 앱 화면 이름
- 수정 가능한 관리자 메뉴
- 수정 필드명
- 앱 반영 위치
- 직접 수정 불가하거나 자동 계산되는 항목의 구분

### 2.2 개발/운영 인수인계 담당자

완료보고서에는 개발 산출물과 기능 범위를 남기고, 사용 보고서에는 관리자 조작 기준을 남긴다.

필요한 정보:
- 사용자 앱과 관리자 메뉴의 1:1 매핑
- 수정 가능/불가 범위
- 콘텐츠와 계정/상태값의 경계

---

## 3. 보고서 명칭

이 문서는 완료보고서 본문에 섞기보다 별도 산출물로 제공하는 것이 맞다.

권장 명칭:
- `아가야 관리자 사용 보고서`
- 보조 제목: `앱 화면별 관리자 수정 위치 매칭표`

완료보고서에는 아래처럼 한 줄로 연결한다.

> 앱 화면별 문구와 관리자 수정 위치는 별도 문서 `아가야 관리자 사용 보고서`에 정리했습니다.

## 6. 수정 가능 여부 기준

- 홈 말풍선/오늘의 한마디/응원 문구
- 주차별 아기/엄마 요약
- 일별 아기 발달/엄마 변화 문구
- 체크리스트 항목
- 태교 질문
- 주차 대표 이미지/비교 이미지
- 임신백과 노출본
- 기분 선택 문구와 대화 흐름
- 기분별 공감 문장
- 외부 설문 이름/링크/노출 여부

### 6.2 관리자에서 조회는 되지만 콘텐츠처럼 수정하지 않는 값

- 사용자별 현재 임신 주차/일차
- 임신 일수
- 출산예정일까지 남은 일수
- 체크리스트 완료율
- 사용자별 체크 완료 상태
- 채팅 세션 기록

이 값들은 운영자가 앱 화면을 이해하는 데 필요하지만, `자산 관리 > 주차별`에서 수정하는 콘텐츠가 아니다. 완료보고서나 사용 보고서에는 “자동 계산/사용자 상태값”으로 표시한다.

### 6.3 현재 관리자 수정 대상이 아닌 앱 고정 문구

- 하단 탭 이름: `홈`, `오늘,우리`, `마이페이지`
- 오늘,우리 내부 탭 이름: `아기와 엄마`, `체크리스트`, `아기와 대화`
- 섹션 제목: `오늘 아기는요`, `오늘 엄마는요`, `오늘의 체크리스트`, `임신백과`, `사용설명서`
- 입력창 placeholder: `아기에게 하고 싶은 말을 적어보세요...`

필요하면 추후 “앱 UI 문구 관리” 기능으로 별도 관리자화할 수 있지만, 이번 사용 보고서에서는 고정 UI 문구로 분류한다.

## 7. 보고서 구성안

최종 전달용 `아가야 관리자 사용 보고서`는 아래 순서로 구성한다.

1. 문서 목적
2. 앱 화면과 관리자 메뉴 매칭 개요
3. 앱 화면별 수정 위치 매칭표
4. 관리자 메뉴별 수정 가능 항목
5. 직접 수정 불가한 자동 계산값 안내
6. 운영자가 수정 요청을 보낼 때의 표준 양식

표준 요청 양식:

| 항목 | 작성 예시 |
| --- | --- |
| 앱 화면 | 오늘,우리 > 아기와 엄마 |
| 수정 대상 | 오늘 엄마는요 본문 |
| 현재 문구 | 피부 가려움이 생길 수 있어요... |
| 변경 문구 | 피부가 건조하거나 가려울 수 있어요... |
| 관리자 위치 | 자산 관리 > 주차별 > 15주차 > 일별 본문 > 2일차 |
| 비고 | 앱 노출 확인 필요 |

---

## 8. 수용 기준

- 사용자는 첨부된 앱 화면을 보고 관리자 수정 위치를 찾을 수 있어야 한다.
- `콘텐츠 수정 가능 항목`과 `자동 계산/조회 항목`이 구분되어야 한다.
- `15주 2일` 같은 사용자 상태값을 주차 콘텐츠 문구로 오해하지 않게 설명해야 한다.
- 완료보고서와 별개 문서로 사용할 수 있는 제목과 구조를 가져야 한다.
- 교수님/운영자에게 전달해도 개발자 용어 없이 이해 가능한 문장이어야 한다.

## 9. 남은 확인 항목

아래 항목은 최종 사용 보고서로 변환할 때 화면 캡처 또는 실제 운영 관리자 URL 기준으로 한 번 더 확인한다.

- 관리자 화면의 실제 메뉴명과 현재 배포본 메뉴명이 동일한지
- 외부 설문 버튼명 `1차/2차/3차 설문지 열기`가 운영 설정과 일치하는지
- 15주 2일 예시 사용자의 출산예정일/주차 계산값이 실제 테스트 계정과 일치하는지
- 사용설명서 화면이 관리자에서 편집 가능한 최신 기능으로 바뀌었는지
