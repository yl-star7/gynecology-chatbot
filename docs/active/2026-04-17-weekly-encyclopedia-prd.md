# 주차별 임신백과 사전 PRD

- 작성일: 2026-04-17
- 상태: Draft v1
- 대상: 모바일 앱, 관리자 웹
- 관련 문서:
  - `docs/reference/PRD.md`

  - `docs/active/2026-04-16-chat-archive-encyclopedia-prd.md`

## 1. 문서 목적

이 문서는 `임신백과`를 채팅형 검색 또는 RAG 답변 기능이 아니라, 산모가 주차별 정보를 사전처럼 조회하는 콘텐츠 기능으로 정의한다.

기존 `2026-04-16-chat-archive-encyclopedia-prd.md`의 임신백과 방향은 검색형 표면과 채팅 전환을 중심으로 설명되어 있다. 본 문서는 그중 `임신백과` 범위를 아래처럼 정정한다.

- 주차별 사전 조회가 핵심이다.
- 자유어 검색과 RAG 답변은 MVP 범위가 아니다.
- 사용자에게 노출되는 콘텐츠는 paraphrase 완료본이어야 한다.
- 관리자 웹은 주차별 원문, paraphrase, 발행 상태, 누락 상태를 검수하는 운영 표면이어야 한다.

## 2. 제품 정의

### 2.1 한 줄 정의

주차별 임신백과는 현재까지 받은 임신백과 데이터를 산모 친화적인 문체로 paraphrase하고, 산모가 현재 주차 또는 선택한 주차 기준으로 태아 발달, 엄마 몸 변화, 생활 가이드를 사전처럼 읽을 수 있게 하는 콘텐츠 기능이다.

### 2.2 핵심 원칙

1. 사전형 콘텐츠다.
   - 사용자가 질문을 입력해 답변을 받는 구조가 아니다.
   - 사용자는 주차와 카테고리를 따라 정보를 탐색한다.

2. paraphrase 완료본만 노출한다.
   - 원문 문장을 사용자 앱에 그대로 보여주지 않는다.
   - 원문은 관리자 검수와 추적 목적에만 사용한다.

3. 주차별 맥락을 우선한다.
   - 현재 주차가 있는 사용자는 해당 주차 사전을 먼저 본다.
   - 다른 주차도 직접 선택해 볼 수 있다.

4. 채팅과 분리한다.
   - MVP에서는 채팅 화면에서 임신백과로 직접 이동하는 CTA를 제공하지 않는다.
   - 채팅 답변 생성을 위한 RAG 파이프라인으로 보지 않는다.

## 3. 배경과 문제 정의

### 3.1 현재 상황

현재 임신 관련 콘텐츠는 `content.pregnancy_week_data`, `content.pregnancy_day_contents`, `content.week_checklists`, `content.week_questions`를 중심으로 운영되고 있다.

기존 import coverage 기준으로는 아래 상태가 확인되어 있다.

| 항목 | 현재 상태 |
|---|---|
| `content.pregnancy_week_data` | draft 17개, published 23개 |
| `content.pregnancy_day_contents` | 161개 |
| `content.week_checklists` | 530개 |
| `content.week_questions` | 387개 |
| published 주차 | 13~35주 |
| draft 주차 | 1~12주, 36~40주 |

현재 데이터는 주차별 콘텐츠의 기초는 갖추고 있지만, 사용자에게 보여줄 최종 사전 콘텐츠로는 아래 문제가 남아 있다.

- 원문 또는 import 문장이 그대로 노출될 수 있다.
- 주차별 화면에서 어떤 콘텐츠가 완성, 미완성, 검수 필요 상태인지 명확하지 않다.
- 사용자가 앱에서 주차별 사전을 읽는 전용 경험이 약하다.
- 관리자 웹에서 paraphrase 상태와 누락 상태를 한눈에 관리하기 어렵다.

### 3.2 사용자 문제

- "이번 주에 아기가 어떻게 자라는지 바로 보고 싶어요."
- "내 몸 변화가 이 주차에 자연스러운 건지 차분히 읽고 싶어요."
- "채팅으로 물어보는 것 말고, 사전처럼 정리된 내용을 보고 싶어요."
- "이전 주차나 다음 주차 정보도 미리 확인하고 싶어요."

### 3.3 운영자 문제

- "어떤 주차가 발행 가능한 상태인지 한눈에 보고 싶습니다."
- "원문과 paraphrase 결과를 비교해서 수정하고 싶습니다."
- "태아 발달, 엄마 몸 변화, 생활 가이드 중 누락된 영역을 확인하고 싶습니다."
- "검수 전 콘텐츠가 사용자 앱에 노출되지 않게 막고 싶습니다."

## 4. 목표와 비목표

### 4.1 목표

1. 현재까지 받은 임신백과 데이터를 paraphrase 대상에 포함한다.
2. 사용자 앱에서 주차별 임신백과를 조회할 수 있게 한다.
3. 현재 산모 주차 기준으로 `이번 주 백과`를 제공한다.
4. 사용자가 다른 주차를 선택해 해당 주차 사전을 읽을 수 있게 한다.
5. 최소 카테고리 `태아 발달`, `엄마 몸 변화`, `생활 가이드`를 제공한다.
6. 사용자 앱에는 `ready` 또는 `published` 상태의 paraphrase 콘텐츠만 노출한다.
7. 관리자 웹에서 원문, paraphrase, 상태, 누락 항목을 관리할 수 있게 한다.

### 4.2 비목표

MVP에서는 아래를 포함하지 않는다.

- 자유어 검색
- RAG 기반 답변 생성
- 채팅 화면에서 임신백과로 직접 이동하는 CTA
- 임신백과에서 채팅으로 이어가기
- 개인 증상 기반 맞춤 사전 추천
- 고도화된 AI 자동 검수 점수
- 복수 paraphrase 버전 비교 UI

## 5. 사용자와 역할

### 5.1 산모 사용자

모바일 앱에서 현재 주차 또는 선택한 주차의 임신백과를 읽는다.

주요 니즈:

- 현재 주차 정보를 빠르게 확인
- 태아 발달과 엄마 몸 변화를 분리해서 이해
- 생활 체크 항목을 부담 없이 확인
- 불안을 키우지 않는 따뜻한 문체로 정보 확인

### 5.2 운영 관리자

관리자 웹에서 주차별 콘텐츠를 관리한다.

주요 니즈:

- 주차별 완료 상태 확인
- 원문과 paraphrase 비교
- paraphrase 본문 수정
- 카테고리별 누락 확인
- 발행 상태 변경

### 5.3 슈퍼 관리자

발행 정책과 민감 콘텐츠 최종 승인 권한을 가진다.

MVP에서는 기존 관리자 권한 체계를 따르되, 추후 의료적으로 민감한 항목 승인 권한을 `super_admin`에만 부여할 수 있다.

## 7. 콘텐츠 구조

### 7.1 주차 단위

임신백과의 기본 단위는 임신 주차다.

각 주차는 다음 구조를 가진다.

| 영역 | 필수 여부 | 설명 |
|---|---|---|
| 주차 요약 | 필수 | 이번 주를 2~3문장으로 설명 |
| 태아 발달 | 필수 | 아기의 성장, 크기, 기관 발달, 움직임 |
| 엄마 몸 변화 | 필수 | 산모가 느낄 수 있는 신체 변화 |
| 생활 가이드 | 필수 | 생활 습관, 체크리스트, 챙길 일 |
| 주의할 점 | 권장 | 병원 상담이 필요한 신호 |
| 자주 궁금한 점 | 권장 | 주차별 질문과 짧은 답변 |
| 이미지/크기 정보 | 권장 | 아기 크기, 비교 사물, 대표 이미지 |

### 7.2 카테고리 정의

| category | 사용자 표시명 | 설명 |
|---|---|---|
| `baby_development` | 태아 발달 | 태아 성장 정보 |
| `mother_body` | 엄마 몸 변화 | 산모 신체 변화 |
| `life_guide` | 생활 가이드 | 생활 관리와 체크리스트 |
| `warning` | 주의할 점 | 진료 또는 상담이 필요한 신호 |
| `faq` | 자주 궁금한 점 | 질문과 답변 |

### 7.3 Day별 데이터와 주차 사전의 관계

현재 데이터는 Day 1~7 단위 콘텐츠를 포함한다. 사용자 앱 사전에서는 Day별 원문을 그대로 나열하지 않는다.

MVP 표시 원칙:

- 주차 요약은 `pregnancy_week_data`의 요약 필드를 기반으로 한다.
- 태아 발달과 엄마 몸 변화는 Day별 본문을 주차 단위로 재구성한 paraphrase 본문을 사용한다.
- 생활 가이드는 체크리스트를 기반으로 하되, 사전 읽기용 설명과 체크 항목을 분리한다.
- 질문은 `week_questions`를 기반으로 하되, 사용자 앱에서는 FAQ 또는 성찰 질문 섹션으로 표시한다.

## 8. Paraphrase 요구사항

### 8.1 처리 대상

현재까지 받은 임신백과 관련 데이터 전체를 대상으로 한다.

포함 대상:

- `content.pregnancy_week_data`
- `content.pregnancy_day_contents`
- `content.week_checklists`
- `content.week_questions`
- 주차별 이미지/크기 메타가 연결된 경우 해당 설명 문구
- 일반 임신 정보 중 특정 주차에 연결 가능한 항목

### 8.2 작성 원칙

Paraphrase는 단순 요약이 아니라, 원문의 의미를 유지하면서 앱의 문체와 화면 구조에 맞게 다시 쓰는 작업이다.

필수 기준:

- 의학적 의미를 바꾸지 않는다.
- 숫자, 주차, 기간, 증상명, 검사명은 임의 변경하지 않는다.
- 원문 문장을 그대로 복사하지 않는다.
- 산모 대상 문구는 `-어요/-해요` 체를 사용한다.
- 불안을 키우는 표현은 줄이고 차분한 표현으로 바꾼다.
- 확정적 진단이나 처방처럼 보이는 표현을 피한다.
- 진료가 필요한 상황은 부드럽지만 명확하게 안내한다.
- 너무 짧게 줄여 핵심 의미가 사라지지 않게 한다.

### 8.3 품질 기준

좋은 paraphrase는 아래 조건을 만족한다.

- 원문과 의미는 같다.
- 문장 구조와 표현은 새로 작성되어 있다.
- 산모가 모바일에서 읽기 쉽다.
- 앱의 따뜻한 문체와 맞다.
- 사전 콘텐츠로 읽어도 자연스럽다.
- 검수자가 원문과 대조했을 때 누락된 핵심 정보가 없다.

### 8.4 상태값

각 paraphrase 콘텐츠는 상태값을 가진다.

| 상태 | 의미 | 사용자 노출 |
|---|---|---|
| `pending` | 아직 작성 전 | 불가 |
| `processing` | 자동 처리 또는 작성 중 | 불가 |
| `needs_review` | 검수 필요 | 불가 |
| `ready` | 사용자 노출 가능 | 가능 |
| `failed` | 처리 실패 | 불가 |
| `archived` | 더 이상 사용하지 않음 | 불가 |

사용자 앱은 `ready` 상태만 조회한다. 기존 DB 상태가 `published`를 사용한다면 MVP에서는 `published`를 `ready`와 같은 노출 가능 상태로 해석할 수 있다. 단, 최종 설계에서는 paraphrase 상태와 발행 상태를 분리하는 것을 권장한다.

## 9. 데이터 요구사항

### 9.1 권장 데이터 모델

기존 주차 데이터는 유지하되, 사용자 노출용 paraphrase 결과는 분리 저장한다.

권장 필드:

| 필드 | 설명 |
|---|---|
| `id` | paraphrase 콘텐츠 ID |
| `source_table` | 원본 테이블명 |
| `source_id` | 원본 row ID |
| `week_number` | 임신 주차 |
| `day_number` | Day 정보가 있는 경우 1~7 |
| `category` | `baby_development`, `mother_body`, `life_guide`, `warning`, `faq` |
| `title` | 사용자 표시 제목 |
| `summary` | 카드 또는 섹션 요약 |
| `body` | paraphrase 본문 |
| `items` | 체크리스트 또는 FAQ 등 구조화 JSON |
| `status` | paraphrase 상태 |
| `review_note` | 검수 메모 |
| `updated_at` | 마지막 수정 시각 |

### 9.2 원본 보존 정책

- 원본 데이터는 관리자 검수와 추적 목적에만 사용한다.
- 사용자 앱 API는 원본 본문 필드를 반환하지 않는다.
- 관리자 웹에서는 권한이 있는 사용자만 원문을 볼 수 있다.
- 사용자 앱에 원문 전체 보기 기능은 제공하지 않는다.

### 9.3 노출 가능 기준

주차가 사용자 앱에 노출되려면 최소 아래 조건을 만족해야 한다.

- 주차 요약이 있다.
- 태아 발달 paraphrase가 `ready`다.
- 엄마 몸 변화 paraphrase가 `ready`다.
- 생활 가이드 paraphrase가 `ready`다.
- 필수 섹션 중 원문 그대로 복사된 문장이 없다.
- 관리자에서 발행 가능 상태로 표시되어 있다.

## 10. 사용자 앱 요구사항

### 10.1 임신백과 진입

사용자는 모바일 앱의 맨 오른쪽 `마이페이지` 탭 안에 있는 `임신백과` 섹션에서 주차별 사전으로 진입한다.

MVP에서는 `임신백과`를 별도 하단 탭으로 노출하지 않는다. 내부 구현은 기존 지식 화면 코드를 재사용할 수 있지만, 사용자-facing 정보 구조에서는 마이페이지 하위 섹션으로 취급한다.

### 10.2 이번 주 백과

사용자의 프로필에 현재 임신 주차가 있으면 `이번 주 백과`가 기본으로 열린다.

표시 정보:

- 현재 주차
- 주차 제목
- 아기 크기 또는 비교 사물
- 주차 요약
- 태아 발달
- 엄마 몸 변화
- 생활 가이드

### 10.3 주차 선택

사용자는 1~40주 중 다른 주차를 선택할 수 있다.

요구사항:

- 현재 주차는 강조 표시한다.
- `ready` 콘텐츠가 없는 주차는 비활성 또는 준비 중 상태로 표시한다.
- 과거/미래 주차도 읽을 수 있다.
- 선택한 주차는 화면 상단에 명확히 표시한다.

### 10.4 카테고리별 조회

한 주차 안에서 카테고리별로 이동할 수 있어야 한다.

MVP 필수 카테고리:

- 태아 발달
- 엄마 몸 변화
- 생활 가이드

권장 카테고리:

- 주의할 점
- 자주 궁금한 점

### 10.5 빈 상태와 준비 중 상태

콘텐츠가 없는 경우 사용자에게 원문 미완료나 시스템 오류처럼 보이면 안 된다.

예시 문구:

- "이 주차 정보는 정리 중이에요. 준비되는 대로 보여드릴게요."
- "아직 확인 가능한 정보가 없어요. 다른 주차를 먼저 살펴봐 주세요."

### 10.6 채팅과의 관계

MVP에서는 채팅 화면에서 임신백과로 직접 이동하는 기능을 제공하지 않는다.

제외:

- 채팅 답변 하단 `임신백과에서 보기`
- 임신백과 상세에서 `이 주제로 상담하기`
- 자유 입력 기반 사전 검색
- RAG 답변 생성

## 11. 관리자 웹 요구사항

### 11.1 콘텐츠 대시보드

관리자는 주차별 임신백과 준비 상태를 한눈에 확인할 수 있어야 한다.

표시 항목:

- 전체 주차 수
- 사용자 노출 가능 주차 수
- 검수 필요 주차 수
- 누락 주차 수
- 카테고리별 누락 현황
- 최근 수정 시각

### 11.2 주차 목록

주차 목록은 1~40주를 기준으로 표시한다.

필수 컬럼:

- 주차
- 제목
- 상태
- 태아 발달 상태
- 엄마 몸 변화 상태
- 생활 가이드 상태
- 질문/FAQ 상태
- 이미지 상태
- 마지막 수정일

필터:

- 전체
- 노출 가능
- 검수 필요
- 누락 있음
- draft
- published 또는 ready

### 11.3 주차 상세

주차 상세에서는 원문과 paraphrase 결과를 비교하고 수정할 수 있어야 한다.

필수 영역:

- 주차 기본 정보
- 원문 미리보기
- paraphrase 편집
- 카테고리별 상태
- Day별 원문 연결
- 체크리스트
- 질문/FAQ
- 이미지/크기 메타
- 발행 전 검수 체크

### 11.4 Paraphrase 편집

관리자는 각 카테고리별 paraphrase 본문을 수정할 수 있다.

요구사항:

- 원문과 paraphrase를 나란히 볼 수 있다.
- paraphrase 본문을 직접 편집할 수 있다.
- 상태를 `needs_review`, `ready`, `archived` 등으로 변경할 수 있다.
- 저장 전 필수 카테고리 누락 여부를 경고한다.
- 사용자 앱 노출 미리보기를 확인할 수 있다.

### 11.5 발행 가드

필수 섹션이 준비되지 않은 주차는 사용자 앱에 노출되지 않아야 한다.

발행 차단 조건:

- 태아 발달 없음
- 엄마 몸 변화 없음
- 생활 가이드 없음
- paraphrase 상태가 `ready`가 아님
- 본문이 비어 있음
- 원문과 동일한 문장 비율이 과도하게 높음

마지막 조건은 MVP에서는 수동 체크리스트로 시작할 수 있다.

## 12. API 요구사항

### 12.1 사용자 앱 API

필요 API:

| API | 목적 |
|---|---|
| `GET /api/mobile/encyclopedia/weeks` | 주차별 노출 가능 상태 목록 |
| `GET /api/mobile/encyclopedia/weeks/[weekNumber]` | 특정 주차 사전 상세 |

MVP에서는 기존 `GET /api/mobile/content-items?section=knowledge`를 확장해도 되지만, 장기적으로는 주차별 사전 API를 분리하는 것이 명확하다.

사용자 앱 응답에는 원문 필드를 포함하지 않는다.

### 12.2 관리자 API

기존 관리자 콘텐츠 API를 활용하되, 아래 기능을 지원해야 한다.

| API | 목적 |
|---|---|
| `GET /api/admin/content/weeks` | 주차 목록과 상태 |
| `GET /api/admin/content/weeks/[weekNumber]` | 주차 상세 |
| `PUT /api/admin/content/weeks/[weekNumber]` | 주차 정보, 섹션, 체크리스트, 질문 저장 |
| `POST /api/admin/content/weeks/[weekNumber]/paraphrase` | paraphrase 생성 또는 재생성 |
| `PUT /api/admin/content/weeks/[weekNumber]/paraphrase/[id]` | paraphrase 수정과 상태 변경 |

`paraphrase` 전용 API는 MVP에서 별도 구현하지 않고 기존 week update payload에 포함할 수 있다. 단, PRD 기준 기능 책임은 분리한다.

## 13. 성공 지표

### 13.1 제품 지표

- 마이페이지 임신백과 섹션 진입률
- 현재 주차 사전 조회율
- 다른 주차 선택률
- 주차별 평균 체류 시간
- 필수 카테고리 열람률

### 13.2 운영 지표

- 1~40주 중 노출 가능 주차 수
- 필수 카테고리 완성률
- paraphrase `ready` 비율
- `needs_review` 잔여 수
- 원문 노출 이슈 0건

## 14. 수용 기준

### 14.1 사용자 앱

- 사용자는 마이페이지의 임신백과 섹션에서 현재 주차 사전을 볼 수 있다.
- 사용자는 다른 주차를 선택해 사전을 볼 수 있다.
- 각 주차는 최소 `태아 발달`, `엄마 몸 변화`, `생활 가이드`를 제공한다.
- 사용자 앱에는 paraphrase 완료 콘텐츠만 표시된다.
- 원문 전체 또는 원문 문단이 그대로 노출되지 않는다.
- 준비되지 않은 주차는 준비 중 상태로 표시된다.
- 채팅형 검색 또는 RAG 답변 기능처럼 동작하지 않는다.

### 14.2 관리자 웹

- 관리자는 1~40주 상태를 목록으로 확인할 수 있다.
- 관리자는 주차별 원문과 paraphrase를 비교할 수 있다.
- 관리자는 paraphrase 본문을 수정하고 상태를 변경할 수 있다.
- 필수 카테고리가 누락된 주차는 발행할 수 없다.
- 발행 가능한 주차만 사용자 앱에 노출된다.

### 14.3 데이터

- 현재까지 받은 임신백과 데이터가 paraphrase 대상에 포함되어 있다.
- 원본 데이터와 사용자 노출 데이터가 분리되어 있다.
- 사용자 앱 API는 원문 본문을 반환하지 않는다.
- 각 paraphrase 항목은 원본 추적용 `source_id`를 가진다.

## 15. MVP 범위

### 15.1 반드시 포함

- 기존 임신백과 데이터 paraphrase 처리 기준 확정
- 주차별 콘텐츠 구조 확정
- 현재 주차 기준 임신백과 앱 화면
- 주차 선택 기능
- 태아 발달, 엄마 몸 변화, 생활 가이드 표시
- 관리자 주차 목록에서 완성/누락 상태 확인
- 관리자 주차 상세에서 paraphrase 수정
- `ready` 상태만 사용자 노출

### 15.2 후속 범위

- 자유어 검색
- 임신백과와 채팅 간 전환
- 자동 paraphrase 품질 점수
- 원문 유사도 자동 검사
- 카테고리 추천
- 개인 증상 기반 콘텐츠 추천

## 16. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| paraphrase 중 의학적 의미가 바뀜 | 신뢰도 저하 | 원문 비교 검수와 민감 표현 가이드 적용 |
| 원문과 너무 유사함 | 저작권/표절 리스크 | 원문 유사도 수동 체크, 표현 재작성 |
| 일부 주차 데이터 누락 | 사용자 경험 단절 | 준비 중 상태 표시, 관리자 누락 대시보드 |
| RAG/채팅 요구사항과 혼동 | 범위 확산 | MVP 비목표에 명시하고 UI에서 검색창 제외 |
| 관리자 편집 범위 과대 | 일정 지연 | 목록, 상세, 상태 변경 중심으로 축소 |

## 17. 결정 필요 사항

1. paraphrase 결과를 기존 주차 테이블에 추가할지, 별도 테이블로 분리할지
2. `ready`와 기존 `published` 상태를 어떻게 매핑할지
3. 1~12주, 36~40주 draft 데이터를 MVP에 포함할지
4. 관리자에서 자동 paraphrase 생성까지 제공할지, 외부 처리 후 import할지
5. 이미지/크기 메타를 MVP 필수로 볼지 후속으로 둘지
