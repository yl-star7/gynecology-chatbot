작성일: 2026-04-24
상태: 확정 (유저 합의 완료, 구현 대기)
상위 문서: `docs/active/2026-04-23-admin-hierarchy-replan.md` (v2의 확장)

## 1. 최상위 구조 (6 섹션)

```
/admin
├─ 대시보드                      [운영 홈]
├─ 채팅 로그                     [read-only]
├─ 자산 관리                     [CRUD + variation 풀]
├─ 사전 (RAG)                    [벡터 소스 전용]
├─ 대화 엔진                     [챗봇 행동 규칙]
└─ 시스템 운영                   [인프라 + 감사 + 사용자 운영 액션]
```

기존 v2의 7개 최상위(대시보드/사용자/콘텐츠/대화엔진/자산/운영)에서:
- "콘텐츠" → **자산 관리에 흡수** (주차별 본문은 자산의 일부, 유저 확정)
- "사용자 관리" → **시스템 운영에 병합** (빈도 낮음)
- "자산 관리"에 "RAG 참조"를 따로 **"사전" 섹션으로 분리** (유저 요구 #6 자유 검색 사전 연결)

## 2. 섹션별 상세

### 2.1 대시보드 (`/admin/dashboard`)

운영 홈. 한 화면에서 건강 진단 + 드리프트 경보.

- KPI 카드: 활성 사용자, 오늘 메시지 수, 평균 응답 시간
- 드리프트 경보: YAML SHA ↔ DB workflow_version ↔ Schift runtime 불일치 표시
- 최근 편집 피드: `admin_audit_logs` 최근 N건 요약

### 2.2 채팅 로그 (`/admin/chats`)

Read-only. 유저 상담 상태 확인용.

- `/admin/chats` — 유저 목록
  - 데이터: `users` + `pregnancy_profiles` join
  - 컬럼: 닉, 주차, 최근 세션 시각, 누적 메시지, 계정 상태
- `/admin/chats/:userId` — 유저 상세 + 세션 리스트
  - 데이터: `chat_sessions` (해당 유저)
- `/admin/chats/:userId/:sessionId` — 메시지 타임라인
  - 데이터: `chat_messages` (해당 세션)
  - **본문 평문 노출** (유저 확정)
  - 화면 진입 시 `admin_audit_logs`에 `action=view_chat_messages` 기록
- `/admin/chats/actions` — 유저 액션 로그 (필터: 유저/type/기간)
  - 데이터: `user_action_logs`

### 2.3 자산 관리 (`/admin/assets`)

모든 편집 대상. 통합 CRUD.

#### 2.3.1 주차별 (`/admin/assets/weeks`)

주차 1~40 좌측 레일 → 우측에 통합 overlay.

통합 overlay에서 한 주차의 다음을 모두 편집:
- 주차 기본 (title, baby_summary, mother_summary, warning_signs, recommended_actions)
- Day × 7 (title, baby_message, baby_development, mother_changes)
- 체크리스트 (Day별 N개)
- 질문 (Day별 N개)
- 주차별 안내 (`knowledge_items` week=N)
- 주차별 이미지 (`pregnancy_week_media` hero/compare/inline)

테이블:
- `content.pregnancy_week_data`
- `content.pregnancy_day_contents`
- `content.week_checklists`
- `content.week_questions`
- `content.knowledge_items` (week 단위)
- `content.pregnancy_week_media`

**기존 `AdminWeekOverlay.tsx` 확장해 knowledge_items + media까지 포함.**

#### 2.3.2 공통 풀 (`/admin/assets/pools`)

주차 무관. variation/random select 대상.

- **홈 위안 풀** (`/pools/home-copy`)
  - 데이터: `system_config.home_copy.variants[]`
  - 모바일 홈 첫화면 문구. 랜덤 select.
- **아기 위안 풀** (`/pools/baby-comfort`)
  - 데이터: [신규] `content.baby_comfort_pool`
  - "오늘의 아기 한마디" 풀. 주차 무관, `tag` optional.
  - 모바일 API 계약 불변 (§5.2 참조)
- **캐릭터 이미지** (`/pools/character`)
  - 데이터: `system_config.character_images` (5 tone: calm/joyful/anxious/tired/sad)
  - tone별 1개씩 현재 활성 이미지 교체

#### 2.3.3 스토리지 설정 (`/admin/assets/storage`)

Read-only 현재 환경 표시.

- GCS 버킷 이름·공개 URL prefix (`gcs-storage.ts` 설정)
- 사용량 (Google Cloud Storage API)
- `process.env.STORAGE_PROVIDER` 현재값

### 2.4 사전 (RAG) (`/admin/lexicon`)

**용어 주의**: 유저 요구 #6 "자유 검색 사전"과 연결된 섹션. "주차별 안내"는 자산의 일부, 여기는 **RAG 검색 대상 문서**만.

- 데이터: `content.pregnancy_documents` + Schift `pregnancy-knowledge` 버킷
- 기능:
  - 파일 업로드 (DB insert + Schift upload)
  - 메타 수정 (title/category/week)
  - 삭제 (DB + Schift 동기)
  - **DB vs Schift 드리프트 표시** (file_count 불일치, metadata 누락 row)
  - **metadata tag 검증 뷰** (week/surface/topic 태그 누락분)
  - (추후) 자유 검색 사전 챗봇 (#6) 연결

### 2.5 대화 엔진 (`/admin/engine`)

챗봇이 어떻게 말하는가.

#### 2.5.1 워크플로우 (`/admin/engine/workflows`)

3층 상태 한 화면 + WorkflowBuilder.

- 상단 배너: YAML git SHA ↔ DB `workflow_versions` ↔ Schift runtime 비교
- 테이블: 워크플로우 목록 (레이어 B)
- 선택 시 임베드된 Schift WorkflowBuilder (레이어 C 편집)
- `workflow_versions` 활용 → **전수 버전 + git 커밋 링크 + 롤백**

#### 2.5.2 기분별 변주 (`/admin/engine/moods`)

- 데이터: [신규] `content.mood_variants`
- UI: scenario × mood 매트릭스 (행=시나리오, 열=감정)
- 셀 클릭 → `prompt_suffix` 편집
- **반영 경로**: 모바일 API가 LLM 호출 전 DB 조회 후 system prompt 끝에 주입. YAML/Schift 배포 불필요 (§5.1 참조)

### 2.6 시스템 운영 (`/admin/ops`)

인프라 + 감사 + 낮은 빈도 운영 액션.

- `/ops/schedule` — 알림 스케줄 (`system_config.schedule`)
- `/ops/branding` — 마스코트/설문 URL (`system_config.branding`)
- `/ops/audit` — 감사 로그 (`admin_audit_logs` 전수 검색)
- `/ops/monitoring` — 집계 지표 + 트렌드 (기존 `AdminMonitoringSection`)
- `/ops/schift` — Schift 단일 진단 (RAG + 워크플로우 인프라 상태, 드리프트)
- `/ops/users` — 사용자 운영 액션
  - 계정 상태 (활성/일시중지/차단)
  - 세션 강제 종료
  - 전화번호 재설정
  - 차단 번호 CRUD (`blocked_phone_numbers`)

## 3. 버전관리 정책

각 리소스 유형별 전략:

| 리소스 | 전략 | 비고 |
|---|---|---|
| 워크플로우 | `workflow_versions` 전수 + git 연결 | 기존 활용 |
| 주차 본문·Day·체크리스트·질문 | `previous_snapshot` jsonb (롤백 1단계) | 신규 |
| 주차별 안내 (knowledge_items) | `previous_snapshot` jsonb | 신규 |
| 주차별 이미지 | `previous_snapshot` jsonb | 신규 |
| 홈 위안 풀 | `previous_snapshot` jsonb (전체 variants 배열 스냅) | 신규 |
| 아기 위안 풀 | `previous_snapshot` jsonb (per-row) | 신규 |
| 기분별 변주 | `previous_snapshot` jsonb (per-row) | 신규 |
| 캐릭터 이미지 | 감사로그만 | GCS 히스토리 활용 |
| 스케줄·브랜딩·차단번호 | 감사로그만 | 롤백 불필요 |
| RAG 파일 | `previous_snapshot` jsonb | Schift 동기 실패 시 복구 위해 |

### 3.1 공통 컬럼 표준

편집 대상 테이블에 추가:
```sql
previous_snapshot  jsonb      -- 마지막 저장 직전 row 전체
updated_by         uuid       -- references users(id)
updated_at         timestamptz DEFAULT now()
```

### 3.2 편집·롤백 동작

저장:
```sql
BEGIN;
  INSERT INTO admin_audit_logs (before=current, after=new, action=update);
  UPDATE t SET previous_snapshot = current_row_as_json(current), (cols) = (new);
COMMIT;
```

롤백 (1단계):
```sql
UPDATE t
SET (cols) = previous_snapshot->>'...',
    previous_snapshot = NULL
WHERE id = ? AND previous_snapshot IS NOT NULL;
```

이전 버전 복원은 `admin_audit_logs`에서 수동 복원 (수동이지만 존재).

## 4. 신규 DB 리소스

### 4.1 `content.baby_comfort_pool`

```sql
CREATE TABLE content.baby_comfort_pool (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  text text NOT NULL,
  tag_week int NULL,                -- null = 공통, 값 있으면 해당 주차만
  tag_mood text NULL,               -- null = 모든 기분, 값 있으면 해당 기분
  active boolean DEFAULT true,
  weight int DEFAULT 1,             -- 가중치 (0 초과)
  previous_snapshot jsonb,
  created_by uuid,
  updated_by uuid,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now()
);

CREATE INDEX ON content.baby_comfort_pool (active);
CREATE INDEX ON content.baby_comfort_pool (tag_week);
```

### 4.2 `content.mood_variants`

```sql
CREATE TABLE content.mood_variants (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  scenario text NOT NULL,           -- baby_info_offer / letter_reflection / ...
  mood text NOT NULL,               -- calm/joyful/anxious/tired/sad
  prompt_suffix text NOT NULL,
  tone text,
  active boolean DEFAULT true,
  previous_snapshot jsonb,
  created_by uuid,
  updated_by uuid,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now(),
  UNIQUE (scenario, mood)
);
```

## 5. 반영 경로 (모바일 API 영향)

### 5.1 mood_variants — 모바일 API 프롬프트 주입

위치: `apps/api/src/routes/mobile/chat.ts` (또는 `packages/mobile-api/src/chat/chat-orchestrator.ts`)

```ts
// LLM 호출 직전
const variant = await prisma.mood_variants.findFirst({
  where: {
    scenario: currentScenario,
    mood: currentMood,
    active: true,
  },
});
if (variant?.prompt_suffix) {
  systemPrompt += `\n\n${variant.prompt_suffix}`;
}
// → Schift workflow / LLM 호출
```

YAML/Schift 배포 불필요. UI 저장 → 다음 대화 즉시 반영.

### 5.2 baby_comfort_pool — API 계약 불변

위치: `apps/api/src/routes/mobile/today.ts`

```ts
// 기존: day_contents.baby_message 1:1
// 신규: 풀에서 seed 기반 랜덤 select
const seed = hashSeed(userId, todayDate);
const pool = await prisma.baby_comfort_pool.findMany({
  where: {
    active: true,
    OR: [{ tag_week: null }, { tag_week: currentWeek }],
  },
});
const selected = weightedRandomPick(pool, seed);
return { ..., baby_message: selected.text };
```

응답 JSON 스키마·필드명 완전 동일 → 앱 수정 0.
