## 1. 배경

실사용 과정에서 현재 상담 경험은 아래 문제를 드러냈다.

1. 사용자는 이전에 나눈 대화를 다시 보고 싶어도 전용 진입점을 바로 찾기 어렵다.
2. 상담 도중 답변이 반복적으로 `임신수첩 체크리스트` 이동으로 마무리되어, 대화가 이어지기보다 중간에 끊기는 느낌을 준다.
3. 빠른 선택지와 후속 문구가 `…`으로 잘려 보여, 사용자가 어떤 선택을 하게 되는지 명확히 이해하기 어렵다.
4. 정보 탐색 목적의 사용과 상담 목적의 사용이 한 화면 안에서 섞여 있어, 사용자는 “대화를 하는 중인지”, “사전형 정보를 찾는 중인지”를 구분하기 어렵다.
5. 사용자가 제공한 참고 자료가 검색 결과나 답변에서 원문 그대로 노출되면 표절 리스크가 생길 수 있다.

이 문서는 위 문제를 해결하기 위해 상담형 경험과 정보 검색형 경험을 분리하고, 저장된 대화 접근성을 높이며, 원문 비노출 정책을 명시하는 제품 요구사항을 정의한다.

## 2. 문제 정의

### 2.1 현재 사용자 문제
- “저장된 채팅을 어디서 다시 봐야 하는지 바로 모르겠어요.”
- “대화를 몇 번 하면 결국 체크리스트로 가면서 대화가 끝나요.”
- “말을 주고받는 느낌보다 빙빙 도는 느낌이에요.”
- “선택지 문장이 잘려서 무엇을 누르는지 애매해요.”
- “사전처럼 찾고 싶은 정보는 따로 검색하고 싶어요.”

### 2.2 현재 구조의 한계
- 저장된 채팅은 Today의 최근 대화, 날짜별 기록, 프로필 캘린더 모달에 흩어져 있다.
- 후속 응답이 `체크리스트 이동` 중심으로 생성되어, 답변 뒤에 이어지는 자연스러운 대화 유도가 약하다.
- 사전형 콘텐츠 진입이 상담 맥락에 종속되어 있어, 사용자가 능동적으로 검색하기 어렵다.
- 인터랙션용 텍스트가 줄임표로 축약되며 의도 전달력이 떨어진다.

## 3. 목표

### 3.1 제품 목표
1. 저장된 상담을 다시 찾는 경로를 명확하게 만든다.
2. 상담은 끝까지 “대화형”으로 유지하고, 정보 탐색은 별도 표면으로 분리한다.
3. `임신수첩 체크리스트` 중심의 단선형 종료 흐름을 없애고, 사용자가 원하는 다음 행동을 직접 선택하게 한다.
4. 사용자가 정보 검색과 상담을 혼동하지 않도록 역할을 분리한다.
5. 사용자용 결과 화면에서는 원문 그대로의 문장 노출을 피하고, 요약·재구성된 정보만 보여준다.
6. 모든 빠른 선택지와 주요 액션 문구는 잘리지 않고 끝까지 읽히게 한다.

### 3.2 비목표
- 관리자 콘텐츠 편집 구조 개편
- RAG 파이프라인 전면 교체
- 상담 모델 교체
- 노트북(개인 기록) 기능 제거

## 4. 핵심 제품 결정

### 4.1 상담과 검색을 분리한다
- `채팅`은 사용자가 상황을 설명하고 답을 주고받는 대화형 경험으로 유지한다.
- `임신백과`는 사용자가 증상, 주차, 검사, 생활 수칙 등을 직접 검색하는 탐색형 경험으로 분리한다.
- 현재 `/knowledge` 표면은 사용자-facing 명칭을 `임신백과`로 통일하고, 목록 중심이 아니라 검색 중심 화면으로 재구성한다.

### 4.2 저장된 대화 진입점은 전용 보관함 경험으로 통합한다
- 과거 세션 재진입 자체는 이미 존재한다.
- 다만 현재는 Today 최근 대화, 날짜별 기록, 프로필 캘린더 모달에 흩어져 있어 전용 보관함처럼 인식되지 않는다.
- 사용자는 날짜, 제목, 최근 대화 내용을 기준으로 이전 상담을 다시 여는 일관된 `대화 보관함` 경험을 가져야 한다.
- 기존 Today/날짜별 기록/프로필 캘린더는 보조 진입점으로 유지하되, “주 진입점”은 명시적인 `대화 보관함`으로 통일한다.

### 4.3 체크리스트/사전 링크는 자동 종료 수단이 아니라 선택형 제안으로 바꾼다
- 답변 직후 자동으로 `임신수첩 체크리스트`로 흐름을 닫지 않는다.
- 후속 액션은 `더 이야기하기`, `임신백과에서 찾아보기`, `기록에 저장하기`, `체크리스트 보기`처럼 사용자가 고를 수 있는 제안으로 제공한다.
- 제안은 대화를 대체하지 않으며, 답변 본문 뒤에 보조적으로 배치한다.

## 5. 정보 구조

### 5.1 사용자 표면 구조
- `채팅 상세` : 기존 `/chat/[sessionId]`
- `대화 보관함` : 신규 `/chat/archive`
- `임신백과` : 기존 `/knowledge`를 검색형 경험으로 재정의
- `내 기록` : 기존 `/notebook`, `/records/[isoDate]`

### 5.2 각 표면의 역할

#### 채팅 상세
- 자유 입력 기반 상담
- 이전 대화 맥락 유지
- 답변, 추가 질문, 저장, 관련 제안 제공

#### 대화 보관함
- 저장된 대화와 최근 대화의 통합 리스트
- 제목, 날짜, 미리보기, 태그(예: 복통, 수면, 검사) 제공
- 대화 재진입, 삭제가 아닌 숨김/정리 중심 UX

#### 임신백과
- 검색창 중심 진입
- 증상, 주차, 검사, 생활 습관, 약물/영양 등 탐색
- 검색 결과는 원문이 아니라 재구성 요약으로 제공
- 필요 시 “이 주제로 상담 이어가기” 액션 제공

#### 내 기록
- 사용자가 저장한 상담, 감정, 체크리스트 이력 확인
- 날짜 맥락에서 다시 보는 개인 기록 표면

## 6. 사용자 시나리오

### 6.1 이전 대화를 다시 보고 싶은 경우
1. 사용자가 프로필 또는 Today에서 `대화 보관함`을 연다.
2. 최근 대화 목록 또는 날짜 필터를 본다.
3. 원하는 대화를 눌러 기존 `/chat/[sessionId]`로 진입한다.

### 6.2 상담 중 더 자세한 정보를 찾고 싶은 경우
1. 사용자가 채팅에서 질문한다.
2. AI가 답변을 제공한다.
3. 답변 하단에 `임신백과에서 자세히 보기` 제안이 노출된다.
4. 사용자가 원할 때만 `임신백과` 검색 결과로 이동한다.

### 6.3 그냥 정보만 빠르게 찾고 싶은 경우
1. 사용자가 `임신백과`를 연다.
2. 검색어를 입력하거나 추천 키워드를 누른다.
3. 재구성된 결과 요약을 읽는다.
4. 필요하면 `이 주제로 상담 이어가기`를 눌러 채팅으로 전환한다.

## 7. 상세 요구사항

### 7.1 대화 보관함

#### 7.1.1 필수 기능
- 최근 대화와 저장된 대화를 한 화면에서 볼 수 있어야 한다.
- 각 항목은 아래 정보를 표시해야 한다.
  - 대화 제목
  - 최근 메시지 또는 요약 미리보기
  - 마지막 업데이트 시각
  - 관련 날짜
- 사용자는 대화를 눌러 해당 세션으로 다시 들어갈 수 있어야 한다.

#### 7.1.2 진입 경로
- Today 대화 섹션 상단에 `전체 보기` 또는 `대화 보관함` CTA 제공
- 프로필 메인 화면에 `대화 보관함` 카드 제공
- 날짜별 기록/캘린더 상세는 기존처럼 특정 날짜 맥락 진입점으로 유지

#### 7.1.3 UX 원칙
- 빈 상태에서는 “대화가 없어요”가 아니라 첫 상담을 유도하는 CTA를 보여준다.
- 최근 대화 1~3개만 부분 노출하는 대신, 사용자가 전체 히스토리의 존재를 명확히 인식할 수 있어야 한다.

### 7.2 채팅 후속 흐름 재설계

#### 7.2.1 답변 구조
채팅 답변은 아래 순서를 기본으로 한다.
1. 사용자의 질문에 대한 직접 답변
2. 주의가 필요한 경우 안전 안내
3. 선택형 후속 제안

#### 7.2.2 선택형 후속 제안 규칙
- 후속 제안은 최대 3개까지 노출한다.
- 제안 예시:
  - 더 이야기하기
  - 임신백과에서 자세히 보기
  - 오늘 기록에 저장하기
  - 체크리스트 보기
- `체크리스트 보기`는 사용자의 의도와 직접 연관될 때만 노출한다.
- `체크리스트 보기`가 노출되어도 대화 입력창은 유지되어야 하며, 대화가 종료된 것처럼 보이면 안 된다.

#### 7.2.3 자동 종료 금지
- 단순 안내 후 바로 링크 카드만 남기고 대화를 사실상 닫는 패턴을 금지한다.
- 상담이 끝나는 경우에도 `대화 마무리` 또는 `오늘은 여기까지`처럼 사용자가 명시적으로 종료를 선택해야 한다.

### 7.3 임신백과

#### 7.3.1 제품 정의
- `임신백과`는 증상/검사/생활관리/주차 정보 탐색을 위한 검색형 표면이다.
- 기존 지식 목록 성격보다 검색 시작 경험이 우선되어야 한다.

#### 7.3.2 필수 기능
- 상단 검색창 제공
- 최근 검색어 또는 추천 키워드 제공
- 결과 리스트 제공
- 결과 상세에서 아래 정보 제공
  - 재구성된 요약 답변
  - 관련 주차 또는 카테고리
  - 주의 문구가 필요한 경우 별도 박스 표시
  - `이 주제로 상담 이어가기` CTA

#### 7.3.3 채팅과의 연결
- 임신백과에서 채팅으로 넘어갈 때는 검색어 또는 선택한 주제를 초기 질문 후보로 넘긴다.
- 반대로 채팅에서 임신백과로 넘어갈 때는 해당 질문과 연관된 검색 결과를 미리 보여줄 수 있어야 한다.

### 7.4 원문 비노출 정책

#### 7.4.1 사용자용 결과 정책
- 사용자에게 보여주는 검색 결과와 지식 답변은 원문 문단을 그대로 복붙해서 보여주면 안 된다.
- 결과는 요약, 재서술, 구조화된 bullet, 핵심 포인트 형태로 제공한다.
- 출처는 문서명, 주차, 주제 등 메타데이터 수준으로 제공한다.
- 사용자용 화면에서 원문 전체 보기 기능은 제공하지 않는다.

#### 7.4.2 허용되는 노출 범위
- 고유 명칭, 검사명, 의학적 용어, 문서 제목 수준의 짧은 표현은 허용 가능하다.
- 한두 문장 수준의 원문 직접 인용도 기본적으로 지양한다.
- 운영/검수 목적의 원문 확인은 관리자 전용 표면에서만 허용한다.

#### 7.4.3 품질 기준
- 요약 결과는 검색 의도와 직접 관련된 내용만 포함해야 한다.
- 사용자가 원문 검색처럼 느끼지 않도록 문장 구조와 표현을 재구성해야 한다.
- 답변이 재서술되더라도 의료 안전 문구는 정확해야 한다.

### 7.5 말줄임표 없는 인터랙션 텍스트

#### 7.5.1 대상
- 빠른 선택지
- 설문 선택지
- 후속 액션 버튼
- 대화 보관함 제목/미리보기의 핵심 액션 텍스트

#### 7.5.2 요구사항
- 사용자가 눌러야 하는 선택지는 기본적으로 전체 문장을 읽을 수 있어야 한다.
- 선택지에 `…`을 넣기 위해 서버에서 문장을 인위적으로 잘라 생성하면 안 된다.
- UI 폭이 부족하면 다음 우선순위로 처리한다.
  1. 2줄 이상 줄바꿈 허용
  2. pill이 아니라 세로형 버튼 리스트로 전환
  3. 그래도 길면 더 짧은 완성형 문구를 새로 생성
- “무엇을 누르면 어떤 의미인지”가 손실되면 안 된다.

## 8. UX 원칙

### 8.1 역할이 섞이지 않아야 한다
- 채팅은 상담
- 임신백과는 탐색
- 내 기록은 회고

### 8.2 대화는 사용자가 이어가고 있다고 느껴야 한다
- 답변 다음에 또 말할 수 있어야 한다.
- 보조 콘텐츠 제안이 대화보다 앞에 오면 안 된다.

### 8.3 기록은 숨겨진 기능처럼 보이면 안 된다
- 사용자는 언제든 이전 대화를 다시 찾을 수 있어야 한다.
- 최근 대화는 “있으면 보여주는 카드”가 아니라 “항상 다시 갈 수 있는 자산”처럼 보여야 한다.

## 9. 성공 지표

### 9.1 정량 지표
- `대화 보관함` 진입률
- 보관함에서 세션 재열람 전환율
- 채팅 세션당 평균 사용자 발화 수 증가
- 답변 후 즉시 이탈률 감소
- 임신백과 검색 사용률
- 임신백과 → 채팅 전환율
- 말줄임표가 포함된 인터랙션 문구 비율 0%

### 9.2 정성 지표
- “대화가 중간에 끊긴다”는 피드백 감소
- “예전 대화를 어디서 보는지 모르겠다”는 피드백 감소
- “원문 그대로 보인다”는 우려 감소

## 10. 수용 기준

### 10.1 대화 보관함
- 사용자는 앱 안에서 전용 `대화 보관함` 진입점을 발견할 수 있어야 한다.
- 사용자는 최근 또는 저장된 대화를 한 화면에서 확인하고 다시 열 수 있어야 한다.

### 10.2 채팅 흐름
- 사용자는 답변 뒤에 다시 말 걸 수 있어야 하며, 링크 카드만 남아 대화가 닫힌 느낌을 받지 않아야 한다.
- 체크리스트/사전형 제안은 답변의 보조 수단이어야 하며, 기본 종료 수단이 아니어야 한다.

### 10.3 임신백과
- 사용자는 `임신백과`에서 검색어 기반으로 정보를 찾을 수 있어야 한다.
- 사용자는 검색 결과에서 원문 문단이 아니라 재구성된 설명을 보게 되어야 한다.
- 사용자는 검색 결과에서 상담으로 자연스럽게 이어갈 수 있어야 한다.

### 10.4 인터랙션 문구
- 사용자가 누르는 모든 주요 선택지는 잘리지 않은 상태로 읽을 수 있어야 한다.
