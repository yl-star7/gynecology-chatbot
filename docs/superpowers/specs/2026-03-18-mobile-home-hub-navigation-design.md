# Mobile Home Hub Navigation Design

## Goal

모바일 경험의 1차 탐색을 단순화한다. 첫 화면은 `홈 허브`로 고정하고, `채팅`은 우하단 FAB로 진입시키며, `프로필/설정/로그아웃`은 우상단 작은 아바타 뒤로 이동시킨다.

이 설계의 목적은 모든 기능을 한 번에 노출하는 것이 아니라, 사용자가 앱을 열었을 때 가장 먼저 봐야 할 정보와 다음 행동만 선명하게 보여주는 것이다.

## User Decisions Captured

- 로그아웃은 첫 화면에서 잘 보이지 않아도 된다.
- 모든 기능이 홈에서 원클릭일 필요는 없다.
- 탐색 구조는 `탭바 없음`을 기본으로 한다.
- `채팅`은 우하단 FAB로 진입한다.
- `프로필`은 우상단 작은 아바타 버튼으로 진입한다.
- `지식`, `수첩`은 홈에서 들어가는 2차 목적지로 둔다.

## Scope

- 모바일 웹과 모바일 앱 공통 정보 구조를 `홈 허브형`으로 재정의한다.
- 각 화면의 책임을 재배치한다.
- 홈, 채팅, 지식, 수첩, 프로필 사이의 진입 원칙을 정한다.
- 로그아웃과 설정 항목의 배치를 재정의한다.

## Out Of Scope

- 새로운 도메인 기능 추가
- 관리자 화면 변경
- 채팅 모델이나 백엔드 API 변경
- 홈 카드 안의 세부 콘텐츠 문구 최적화
- 테마 시스템 자체 개편

## Navigation Model

### Primary Entry

- 앱 진입 기본값은 항상 `홈`
- 하단 탭바는 제거
- 전역 1차 행동은 `채팅 FAB`
- 전역 계정/설정 진입은 `우상단 아바타`

### Route Roles

- `/` 또는 모바일 홈 route: 오늘 상태 확인, 최근 상담 재진입, 2차 목적지 진입
- `/chat/new`: 새 상담 시작
- `/chat/[sessionId]`: 기존 상담 이어가기
- `/knowledge`: 읽는 콘텐츠
- `/notebook`: 저장된 기록, 체크리스트, 메모 정리
- `/profile`: 내 정보, 개인화 설정, 로그아웃

## Screen Responsibilities

### Home

홈은 `보는 곳 + 들어가는 곳`이다. 편집형 설정은 두지 않는다.

노출 우선순위:

1. 상단 바
2. 오늘 요약 히어로
3. 최근 상담 이어가기
4. `지식` / `수첩` 진입 카드
5. 보조 기록 섹션

홈에 남기는 요소:

- 현재 주차, 오늘 상태, 짧은 안내 문장
- 최근 상담 1~2개
- `지식` 카드
- `수첩` 카드
- 필요 시 캘린더/기록 요약 일부

홈에서 제거하는 요소:

- 로그아웃
- 테마 변경
- 채팅 톤 설정
- 알림 시간 변경
- 병원/예정일/태명 편집 UI

### Chat

채팅은 실제 상호작용 화면이다.

- FAB는 항상 `새 채팅 시작` 의미만 가진다.
- 여러 기능을 품은 멀티 액션 메뉴로 확장하지 않는다.
- 기존 상담 재진입은 홈의 `최근 상담`에서 해결한다.

### Knowledge

지식은 읽는 목적지다.

- 홈에서 카드로 진입
- 전역 1차 탐색이 아니라 문맥형 2차 목적지
- 홈으로 복귀했을 때 다시 허브 문맥이 유지되어야 한다.

### Notebook

수첩은 저장/정리 목적지다.

- 홈에서 카드로 진입
- 사용 빈도는 높을 수 있지만, 홈 밖의 별도 1차 탭으로 승격하지 않는다.
- 홈 허브 모델을 유지하기 위해 `기록하러 들어가는 곳`으로 분리한다.

### Profile

프로필은 `내 정보 보기 + 바꾸기` 화면이다.

담당 요소:

- 이름, 전화번호
- 예정 출산일, 태명, 병원
- 현재 주차 관련 요약 정보
- 알림 시간
- 채팅 톤
- 테마
- 로그아웃

프로필에서 다루지 않을 요소:

- 최근 상담 피드
- 지식/수첩 메인 진입
- 홈 대체 역할

## Home Layout Structure

### Top Bar

- 좌측: 짧은 홈 타이틀 또는 오늘 인사
- 우측: 작은 원형 아바타 버튼

아바타는 `설정으로 들어가는 문`으로만 읽혀야 하므로, 상단 프로필 헤더 전체를 누르는 구조는 피한다.

### Hero

가장 먼저 보여주는 정보는 `오늘 바로 확인해야 하는 것`이다.

- 현재 주차
- 짧은 상태 문장
- 오늘 기록 여부 또는 가벼운 안내

히어로는 정보 압축 블록이어야지, 카드 묶음의 시작점처럼 보이면 안 된다.

### Continue Section

최근 상담은 홈에서 예외적으로 바로 노출한다.

- 마지막 세션 1~2개 우선
- 세션이 없으면 첫 상담 시작 안내

이는 `채팅은 FAB` 원칙을 깨는 것이 아니라, `이어가기`를 지원하는 허브 기능이다.

### Destination Cards

`지식`과 `수첩`은 탭처럼 보이지 않고, 홈 안의 목적지 카드처럼 보여야 한다.

- 같은 위계
- 짧은 설명 포함
- 오늘 맥락과 연결되는 문구 우선

### Optional Summary

월간 기록, 감정 캘린더, 기타 요약은 하단 보조 섹션으로 밀어낸다.

홈의 핵심은 요약과 분기이지, 전체 데이터 나열이 아니다.

## Profile Layout Structure

프로필은 피드 화면이 아니라 설정 화면처럼 읽혀야 한다.

권장 섹션:

1. 계정 요약
2. 프로필/임신 정보 편집
3. 개인화 설정
4. 로그아웃

`홈으로`, `새 상담 시작` 같은 보조 바로가기는 필요할 수 있지만, 화면의 주요 위계가 되면 안 된다.

## Interaction Rules

- 앱을 열면 항상 홈에서 시작
- 새 상담은 항상 FAB
- 기존 상담은 홈 `최근 상담` 또는 내부 링크로 진입
- 프로필은 아바타 버튼을 통해서만 진입
- 로그아웃은 프로필 내부 하단 액션
- 지식/수첩은 홈 카드에서만 진입

## Error Handling And Empty States

- 최근 상담이 없으면 `첫 상담 시작` 안내를 홈에 노출
- 프로필 정보가 비어 있으면 `미설정` 상태를 허용하되, 편집 흐름은 유지
- 홈 데이터 일부가 늦어도 아바타/FAB/카드 진입은 막지 않는다.
- 홈에서 보조 데이터 로딩 실패가 나더라도 허브 기능 자체는 유지해야 한다.

## Architecture Impact

현재 구조상 웹 `MobileShell`은 상단 프로필 정보, 상단 가로 탐색, 로그아웃 버튼을 함께 렌더링한다. 이 설계가 적용되면 다음 경계가 필요하다.

- 공통 쉘은 `상단 최소 바 + 선택적 아바타 + 선택적 FAB` 중심으로 단순화
- 화면별 navigation affordance는 각 화면 책임에 맞게 축소
- 홈만 목적지 카드를 관리
- 프로필만 설정/로그아웃을 관리

모바일 앱과 모바일 웹의 구조 차이도 줄여야 한다. 현재 네이티브는 하단 탭과 FAB를 같이 쓰고, 웹은 상단 칩 탐색을 쓰므로, 둘 다 `탭 제거` 기준으로 재정렬되어야 한다.

## Testing Direction

- 홈 렌더 테스트: 탭바 없이 히어로, 최근 상담, 목적지 카드, 아바타/FAB 존재 검증
- 프로필 렌더 테스트: 설정 항목과 로그아웃이 홈에서 분리되었는지 검증
- 채팅 진입 테스트: FAB가 항상 새 채팅 route로 이동하는지 검증
- 라우팅 테스트: 지식/수첩은 홈 카드에서만 주 진입 경로가 되는지 검증
- 회귀 테스트: 기존 세션 이어가기가 홈 최근 상담에서 정상 동작하는지 검증

## Risks And Guardrails

- 홈에 너무 많은 요약 카드를 다시 넣으면 허브 구조가 무너진다.
- 프로필에 피드형 콘텐츠를 추가하면 설정 화면의 역할이 흐려진다.
- FAB를 멀티 액션으로 바꾸면 `새 채팅`의 학습 비용이 다시 올라간다.
- 지식/수첩을 다시 전역 탭으로 올리면 이번 설계의 핵심 결정을 되돌리게 된다.

## Notes

- 이 설계는 정보 구조와 책임 분리에 집중한다.
- 구현 단계에서는 기존 `MobileShell`, 홈 화면, 프로필 화면, 모바일 앱 탭 레이아웃을 함께 정리해야 한다.
