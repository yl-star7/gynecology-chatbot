# 모성간호 챗봇 PRD 범위 기준서 (SOW 부속서 A)

> 목적: "어디까지 구현되는지"를 계약적으로 고정하기 위한 기준 문서
> 버전: v1.1 (Locked)
> 기준일: 2026-02-24
> 적용 문서: `docs/DEVELOPMENT_SOW.md`
> 잠금 산출물(PDF): `docs/PRD_SOW_SCOPE_BASELINE_v1.1_locked.pdf`
> 무결성 확인: `docs/PRD_SOW_SCOPE_BASELINE.sha256`
> 변경 요약(v1.0 -> v1.1): 기능 경계를 정량/데이터/연동/CR 트리거 수준으로 세분화

## 1) 문서 우선순위 (Order of Precedence)

1. 상업/법적 조건(대금, 일정, 책임, 손해배상)은 SOW를 따른다.
2. 기술/기능 구현 범위는 본 PRD(부속서 A)를 따른다.
3. 충돌 시 해석 우선순위는 "SOW(상업/법적) -> PRD(기술/기능)"로 한다.

## 2) 범위 고정 원칙

- 본 문서의 FR/AC/NFR/LIM/INT/DATA ID에 명시된 항목만 계약 범위로 본다.
- 명시되지 않은 기능, 정책, 화면, 데이터 처리, 외부 연동은 범위 외다.
- 범위 외 항목은 CR 승인 전까지 착수하지 않는다.

## 6) 의존성 및 가정 (Dependencies / Assumptions)

- 발주자는 도메인, 브랜딩, 의료자료, 카드뉴스 원본, 검수 담당자를 일정 내 제공한다.
- 발주자 피드백/승인/자료 제공 지연은 일정 조정(연장) 사유로 본다.
- 외부 공급사(API/SMS/클라우드) 정책 변경, 장애, 과금 변경은 CR 대상이다.

## 7) 변경관리 (CR) 및 트리거 매트릭스

1. 요청 접수: 요청자는 기능 ID 또는 한도 ID 단위로 변경사항을 서면 제출한다.
2. 영향 분석: 수급자는 비용/일정/리스크 영향도를 문서로 회신한다.
3. 승인 절차: 양측 서면 승인 전 개발 착수 불가.
4. 기준선 갱신: 승인 시 버전을 상승(v1.1 -> v1.2)하고 PDF+SHA를 재잠금한다.

| CR 트리거 ID | 트리거 조건                               | 처리 원칙 |
| ------------ | ----------------------------------------- | --------- |
| CR-TRG-001   | 본 문서에 없는 신규 기능/화면/역할 요청   | CR 필수   |
| CR-TRG-002   | LIM 한도(건수/기간/비용) 초과             | CR 필수   |
| CR-TRG-003   | 외부 시스템 신규 연동/교체                | CR 필수   |
| CR-TRG-004   | 데이터 모델 구조 변경(신규 핵심 엔터티)   | CR 필수   |
| CR-TRG-005   | 납품 후 운영 기간 연장/유지보수 방식 변경 | CR 필수   |

## 8) 검수 및 간주 승인

- 납품물 제출 후 발주자는 영업일 기준 5일 내 합격/불합격 사유를 서면 통지한다.
- 기한 내 서면 반려가 없으면 해당 마일스톤은 합격으로 간주한다.
- 반려 시에는 AC ID 기준으로 미충족 항목과 재현 절차를 명시해야 한다.
- 검수 양식은 `docs/PRD_ACCEPTANCE_CHECKLIST_v1.1.md`를 기준으로 한다.

## 9) 계약서 삽입용 경계 문구

"본 PRD(부속서 A) v1.1 및 해당 SHA256 무결성 파일에 명시되지 않은 기능, 외부 시스템 통합, 신규 화면/정책 변경, 데이터 정제/마이그레이션, 추가 디자인 개편은 계약 범위 외이며, 별도 Change Request 및 견적 합의 후 수행한다."
